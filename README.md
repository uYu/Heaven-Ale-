# 天堂与美酒 · Heaven & Ale

可在浏览器完整进行的基础版四人局：你经营一座修道院，与三位本地 AI 进行六轮竞赛。中文界面，原生 SVG 棋盘、花园与人物头像，不依赖账号、模型 API 或远程素材服务。

## 运行

需要 Node.js 22.6+（建议当前 LTS）。

```bash
npm ci
npm run dev
```

浏览器打开 http://127.0.0.1:5173 。

```bash
npm run build        # 类型检查并生成 dist/
npm run preview      # 本地预览生产构建
npm test             # 规则回归测试与 20 局自动对战
npm run simulate -- 50  # 指定数量的 AI 自对局
```

## 操作

1. 在道路上点击高亮行动格。也可展开“查看市场全部板块”，先查看堆叠的资源和修士。
2. 购买时先选板块，再点击个人花园空格。阳面支付双倍费用、激活后生产资源；阴面支付原价、激活后获得金币。
3. 同一市场格可连续购买多块。至少买一块后，点击“查看本回合结果”，最后点击“确认本回合”才交给下一位玩家。
4. 移动、购买、计分、出售特权和奖励选择都是预操作，确认前可“撤回一步”或“重做本回合”。预操作也会保存，刷新后仍可撤回。AI 与下一轮补牌仅在确认后继续。
5. 棚屋、计分、特权与起点奖励会在操作栏逐步提示。棚屋可直接点击花园选择方向，也可选择列出的合法组合。
6. 点击任意玩家卡片或花园标签查看对手；左侧导航可查看酒桶目标、完整日志和中文规则。
7. 第六轮结束后自动计算兑换、金币补步与各项得分。展开结算明细查看五种资源前后位置和每次兑换。

个人板包含共用的实体格生产轨道：资源方块与酿酒师棋子显示真实位置，虚线表示本回合操作前的位置，轨道旁标出兑换与倍率门槛。计分板包含十个圆片凹槽及五组特权卡位；进入计分行动后可以直接点击可用凹槽。

手机默认显示带方向箭头的环形道路，可切换完整地图；花园适配屏幕宽度，生产轨道可横向滑动，导航位于底部。桌面保留公共地图和完整个人板，操作栏随滚动保持可见。兑换说明默认折叠，轨道用分区底色和边界标记兑换档位。特权选项显示具体收益，确认页显示新领取的酒桶明细。交互支持键盘与减少动态效果偏好。

## 已实现规则

- 原版 27 个行动格的顺序和修士价格，37 格个人棋盘（15 阳面、15 阴面、7 棚屋）。
- 四人六轮、起点四个独立位置、原顺时针座次、最后返回者强制填补空缺先手位、市场累积与补充。
- 100 块资源、24 块修士；按 I / II 顺序补充。固定种子洗牌。
- 多次购买、阳阴面价格、资源与金币激活、修士触发与被激活的区别、资源溢出金币。
- A / B / C / 任意计分、十个一次性计分位、五组特权配对、五种特权、应急出售。
- 五种棚屋及其方向限制、一次放置完成多个棚屋时逐个处理。
- 十二个酒桶目标、大小桶争夺、单个玩家不能重复领取同一目标。
- 酿酒师完整兑换率与倍率、资源平衡、金币补步、酒桶特权、最终先手分及并列胜利。

本地开局约定：真人固定先手；三位 AI 按逆时针选取剩余起始奖励。终局自动执行资源平衡与金币补步，无需手工移动指示物。修士采用四种中文代称，插画和棋盘样式重新制作。

规则依据：[英文基础版规则](https://www.rulespal.com/heaven-and-ale/rulebook)、[原版规则书 PDF](https://cdn.1j1ju.com/medias/2d/ee/e8-heaven-ale-rulebook.pdf)。棋盘形状、配对、起始位置和倍率表按规则书图示核对。

## AI

设置中可以选择三档，对三位对手统一生效；默认困难，刷新后恢复默认，难度不改变存档的行动重放规则。

- **基线 · 原版 AI**：原来的 `ai.ts` 已逐字保留为 `src/game/ai.baseline.ts`。保留原权重、现金不足时的处理和种子扰动，用于对战与回归。`chooseAction(state)` 默认仍调用基线。
- **普通 · 改进评估**：独立的 `ai.normal.ts`，考虑酿酒师兑换/倍率门槛，用真实激活方向估算棚屋奖励；出售特权时计入失去卡牌的代价。仍属于单步启发式。
- **困难 · 搜索与终局模拟（第二版）**：前两轮沿用上一版困难的建园策略，第三轮起启用新的完整回合规划。先比较不同目的地和完整回合方案，再为有希望的购买路线扩展落点。每个假设牌局都模拟到最终结算，对手在原版、普通和混合策略之间切换。至少完成两组配对模拟后逐步淘汰落后方案，将剩余计算留给优选方案。评价同时考虑得分、领先幅度和跨场景波动。

第三轮起默认先保留最多 28 个完整回合候选，对前四条路线补充购买落点，最多进行八组假设牌局比较，总预算 36000 次规则转换。候选数和预算可以通过 `searchAction` 参数调整；节点预算不是硬性毫秒时限，开局和复杂购买的思考时间可能达到数秒。购买、出售、棚屋和回合结束共同组成计划；Worker 为每位 AI 保留独立计划，只有公开局面完全匹配才直接执行下一步，撤回、导入或局面变化会触发重算。后续缓存步骤通常很快。

未知牌堆从公开市场和花园重建，I / II 时代保持分开；不会读取真实未来牌序、开局种子或历史来预测未知牌。相同公开状态下的搜索是确定性的。所有候选使用相同的假设场景；未完成的模拟不会参与比较，新增落点必须补齐与原方案相同的场景，才有资格替换原计划。

模拟通过 `applySimulationAction` 与正式 `applyAction` 共用规则执行器。分支模拟只复制可变容器、共享不会被规则修改的板块值；终局模拟在独立副本上连续推进，并省略历史复制；完整对局逐步对照测试验证两条路径的状态一致。棋盘邻接关系也改为预计算，减少重复扫描。

上一版困难源码冻结为 `src/game/ai.hard-v1.ts`，原版贪心仍冻结为 `src/game/ai.baseline.ts`，两份都有 SHA-256 回归测试。界面仍保留原版、普通、困难三档；上一版困难可用 `hard-v1` 参数在脚本中对战，全程使用新搜索的开发对照可用 `search-v2`。`chooseAction(state)` 仍默认基线；有连续决策需求时用 `createAgent('hard')` 获取独立、有回合计划的 AI，Worker 与对战脚本使用同一入口。

```bash
npm run benchmark:ai -- 10 1000 hard baseline  # 10 个种子 × 4 个座位，困难对三个基线
npm run benchmark:ai -- 10 3000 hard normal    # 困难对三个普通
npm run benchmark:ai -- 10 2000 normal baseline
npm run benchmark:ai -- 2 9000 hard hard-v1 normal # 新旧困难各一位，另两位普通，轮换座位
```

脚本报告并列分摊胜率、平均得分、相对最强对手分差、决策时间中位数/P95/最大值，并逐步检查状态不变量。每个种子轮换全部四个座位；置信区间按种子分组粗略估计，小样本不足以证明稳定胜率。当前验证见 `docs/ai-v2-validation.md`；首版历史数据保留在 `docs/ai-validation.md`。种子少于 10 个时脚本不再输出不可靠的正态近似区间。

## 保存

每一个规则步骤结束后自动保存到浏览器 `localStorage`，包括尚未结束的购买、棚屋和特权选择。存档保存版本、随机种子与完整行动序列，导入时重放并校验规则，拒绝非法存档。

设置中可以导入、导出 JSON，暂停对局或切换 AI 速度。导入或新开局会替换当前自动存档；清理浏览器数据会丢失本地存档，可事先导出。读取损坏存档失败时保留原始内容，直到用户选择保存新局。存储空间不可用时显示保存失败提示。

## 代码结构

```text
src/game/data.ts       棋盘、配对、卡牌、倍率等静态数据
src/game/types.ts      状态与行动类型
src/game/engine.ts     确定性规则、合法行动、状态不变量、结算
src/game/ai.ts         难度路由（默认保留基线）
src/game/ai.baseline.ts 原版 AI，固定对照
src/game/ai.normal.ts  改进启发式与候选排序
src/game/ai.search.ts  候选筛选、落点扩展、终局模拟与回合计划
src/game/ai.hard-v1.ts 上一版困难 AI，固定对照
src/game/ai.worker.ts  浏览器工作线程
src/game/storage.ts   存档重放、预操作保存与校验
src/game/session.ts   未确认回合、逐步撤回、整回合重做和确认边界
src/components/PlayerBoards.tsx  生产轨道、棋子与实体计分板
src/App.tsx           棋盘、花园、操作栏、日志、设置与结算
src/components/MonkIcon.tsx  修士与酿酒师头像
src/game/preview.ts    特权收益预览
src/style.css         基础界面样式
src/tabletop.css      桌游布局、手机适配与图标样式
```

测试覆盖移动、购买、激活、修士非递归行为、棚屋阈值与方向、特权、全部酒桶目标、换轮、终局结算、存档重放和完整自对局。`scripts/qa-fixtures.ts` 可生成特殊阶段的真实重放存档，用于浏览器手工验收：

```bash
node --experimental-strip-types scripts/qa-fixtures.ts
```

第一版范围为本地单人对三 AI；不含扩展、在线房间或多真人同步。

## 开发与提交检查

```bash
npm ci
npm run format:check
npm run build
npm test
```

使用 `npm run format` 统一格式。两份冻结的 AI 对照源码不参与格式化，以保留哈希回归校验。GitHub Actions 在推送和拉取请求时执行格式检查、构建及测试。

`node_modules/`、`dist/`、`tmp/`、环境变量文件和本地编辑器配置均不进入仓库。存档保存在浏览器本地，不会随源码提交。`docs/` 保留 AI 验证记录，便于复核策略变更；大规模基准对战需手动执行，不作为每次提交的快速检查。
