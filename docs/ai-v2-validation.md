# 困难 AI 第二版 · 分阶段策略

## 保留的对照

- `src/game/ai.baseline.ts`：原版贪心，SHA-256 `becf3e0177405aac143e7868dc1286456ee5b843c9d23cf472ba4402c68c7820`。
- `src/game/ai.hard-v1.ts`：上一版困难，SHA-256 `be8e1e086f5d50b887dc2bf19e5c40b49cdf859e2396fad9e7551aabbfc0b787`。

两者均有源码校验测试。共享棋盘数据的邻接计算经过等价优化，但两份 AI 的源码、权重和决策规则保持原样。

## 本次改动

当前默认困难在前两轮使用冻结的上一版困难策略，第三轮起切换为下面的新规划器。这个选择来自开发验证：全程新搜索对普通对手表现很好，但与旧困难直接比较得分只有三胜、一平、四负，因此没有将它直接作为最终默认。

1. **扩大路线覆盖**：枚举合法目的地，购买保留各板块的阴/阳落点、临近棚屋缺口等候选；完整回合方案先按根动作分组，再分配候选名额，减少近似落点挤占全部搜索空间的问题。
2. **重点优化落点**：初选路线完成两组配对模拟后，对前四条路线补充不同购买落点。新增方案必须在相同场景下模拟到终局，才能与原方案比较。
3. **更广的终局模拟**：对手模型轮换原版、普通及混合策略；至少两组后再淘汰较差候选，最多八组。目标兼顾得分、领先幅度与跨场景波动，预算 36000 次规则转换。
4. **执行完整计划**：每位 AI 拥有独立计划。只有公开状态精确匹配才复用下一个动作；状态变化、撤回、导入会重算。计划在交给其他玩家或换轮时结束，未知牌不会进入缓存键。
5. **减少模拟开销**：邻接表预计算；分支模拟只复制可变容器，终局模拟在独立副本上连续推进，省略历史复制。正式执行和模拟共用一个规则执行器，避免复制一套游戏规则。

候选数量、场景数量和预算都有限，依然属于近似搜索。它不会精确模拟另一位困难 AI 的全部思考，也不是无敌策略。某些开局或复杂购买需要数秒，后续计划步骤可直接执行；时延统计中包含这些缓存步骤，因此中位数不能解释为完整搜索耗时。

## 验证方法

冻结分阶段策略后，使用 9000 段种子验证新旧困难同桌：待测座位为新版，对面座位为旧困难，其余两位普通，每个种子轮换四个座位。另用 10000 段种子验证新版对三个普通。

只将这两个批次作为当前默认策略的结果。5000 / 6000 段来自尚未增加落点扩展的原型；7000 / 8000 段来自全程新搜索的对照，不与默认策略混算。全程新搜索的原始对照结果保存在 `ai-v2-broad-search-duel.txt` 和 `ai-v2-broad-search-normal.txt`，可用 `search-v2` 参数复现。不能直接用不同种子的平均分证明强度提升，因此特别保留了同桌新旧困难的分数比较。

```bash
npm run benchmark:ai -- 2 9000 hard hard-v1 normal
npm run benchmark:ai -- 2 10000 hard normal
```

每一步都执行状态不变量检查。整体胜率指四人局夺冠率，并列分摊；直接对比胜率仅比较新旧困难两人的得分，平分算半胜。种子数量仍少，需要更多种子和真人反馈检验稳定性。

## 已完成的普通对手验证

种子 10000–10001，每个种子轮换四个座位，新版对三个普通 AI：8 局中赢 6 局，胜率 75%；新版平均 44.5 分，对照平均 15.0 分，对最强对照平均领先 21.75 分。完整记录见 `ai-v2-vs-normal-results.txt`。

这些是不同种子的结果，不能把它们与上一版的平均分直接相减作为强度提升量；新旧困难同桌对比单独报告。当前批次有两局输给普通对手，仍然存在策略波动。

本机决策时间中位数约 111 ms，P95 约 1367 ms，最大约 4103 ms。这包括前两轮的旧困难决策、后期新搜索和计划缓存步骤；不是每次完整搜索都只需 111 ms。

## 新旧困难同桌的最终结果

种子 9000–9001，轮换四个座位；每局一位新版、一位旧困难、两位普通。只比较新旧困难的最终得分，新版 **6 胜、0 平、2 负**，得分胜率 **75%**。新版均分 **23.25**，旧困难均分 **21.625**，平均领先 **1.625** 分。完整记录见 `ai-v2-vs-previous-results.txt`。

四人局夺冠率另为 **62.5%**（5 / 8 局），不能与上面的新旧二者比较胜率混淆。两局输给旧困难的分差较大，说明策略仍有弱点。仅两个种子，不据此宣称统计上稳定压倒旧版。

该批次决策中位数约 90 ms，P95 约 1116 ms，最大约 3542 ms，同样包含计划缓存步骤。全部 8 局正常结束，共 2769 个正式行动，每步不变量检查通过。

默认困难的最终验证合计 16 局；开发对照结果另外保存，未计入这 16 局。修改前后的对局规则、起始奖励、计分公式均保持一致，原版基线及旧困难的源码校验通过。
