# 公开回放与腾讯云部署

使用一台腾讯云服务器运行 Node.js 与 SQLite。浏览器继续保留本地存档，服务端保存已确认的行动；仅当规则引擎判定对局结束后，公开列表和详情接口才允许读取。无需注册账号，每场对局有独立随机上传凭证；凭证保留在原浏览器，不包含在导出的游戏 JSON 或公开回放中。

## 本地运行

需要 Node.js 22.13 或更新版本（支持内置 `node:sqlite`）。两个终端分别运行：

```sh
npm ci
npm run server
```

```sh
npm run dev
```

Vite 将 `/api` 转发到 `127.0.0.1:3001`。浏览器打开 `http://127.0.0.1:5173`。主菜单的“公开对局回放”显示已完成的对局。服务未启动时，游戏仍可进行，上传队列在浏览器中等待重试。

生产构建也可以直接由后端提供：

```sh
npm run build
npm run server
```

默认仅监听本机，地址为 `http://127.0.0.1:3001`。数据库位于 `data/replays.sqlite`，不要把它放在临时目录或随构建清理的目录。

## 腾讯云单机 Docker 部署

仓库没有包含服务器地址或登录凭证，本次代码不会自动连接、修改任何服务器。

1. 在服务器安装 Docker Engine 与 Docker Compose 插件，把代码放在固定部署目录。
2. 在腾讯云安全组和服务器防火墙放行 TCP 8200，无需域名或 `.env` 文件。
3. 在项目目录执行：

```sh
docker compose up -d
docker compose ps
docker compose logs --tail=100 app web
```

打开 `http://服务器公网IP:8200` 即可访问。Caddy 在 8200 端口提供 HTTP 并代理网页与 `/api`，不占用宿主机的 80、443 端口。后端端口只在容器网络内可见；`TRUST_PROXY=1` 仅适用于这种可信反向代理配置，代理会覆盖真实来源 IP 头。直接启动 Node 时不要启用此选项。

打开 `http://服务器公网IP:8200/api/health` 检查 返回 `ok: true`，再完成一局，确认“已公开回放”提示及公共列表。由于没有你的服务器环境，本地验证不能代替实际服务器网络和容器上线检查。HTTP 访问支持对局上传；浏览器若不允许自动复制回放链接，可以复制地址栏中的链接。以后如需 HTTPS，可在 8200 端口前加已有的 HTTPS 反向代理。

`app` 已配置 `pull_policy: build`，每次 `docker compose up -d` 都会基于当前目录代码重新构建镜像，未变化的步骤复用构建缓存，无需额外加 `--build`。更新前请先把最新代码同步到部署目录。

更新代码后可直接执行 `docker compose up -d`，也可以按以下方式先停止再启动：

```sh
docker compose down
docker compose up -d
```

启动完成后刷新浏览器。普通 `down` 会保留数据卷。SQLite 存在名为 `replay_data` 的持久卷中。固定使用相同 Compose 项目名/部署目录；改变项目名会创建另一套卷，看起来像空数据库。不要执行 `docker compose down -v`，该命令会删除存档卷。

## 备份与恢复

在线生成一致的 SQLite 备份：

```sh
docker compose exec app node --experimental-strip-types server/backup.ts /app/data/backups/replays-backup.sqlite
docker compose cp app:/app/data/backups/replays-backup.sqlite ./replays-backup.sqlite
```

备份文件名应每次不同；已有目标文件不会被覆盖。定期将备份复制到服务器之外。不要只拷贝运行中的主 `.sqlite` 文件：最新事务可能仍在 WAL 中。

恢复到同一持久卷时，先停止 app，备份旧卷，然后用维护容器将备份放到 `/app/data/replays.sqlite`，移除旧数据库对应的 `-wal` 与 `-shm` 文件，并确保文件可由 UID 1000 读写，再启动 app。先在独立测试卷验证备份，不要直接覆盖唯一的生产副本。

## 存储和公开规则

- 上传内容只有规则版本、种子、人数/座次设置和正式行动；待确认草稿只留在本机。没有姓名、邮箱、IP、浏览器指纹字段。
- 服务端用同一规则引擎重放校验，计算是否结束和最终分数，不信任客户端传来的胜负或分数。额外字段不会进入公开记录。
- 进行中的对局持久保存，但匿名读取详情返回 404，公共列表也不会列出它。终局上传成功后才公开。
- 已接收的行动只能追加，不能改写。乱序到达的旧进度不覆盖新进度；重复上传同一个对局 ID 不会生成重复条目。
- 游戏回放可播放/暂停、调速、逐步前后、拖动进度、跳转结局、查看各玩家棋盘和复制链接。观看不会启动 AI、写入本地游戏存档或再次上传回放。
- 浏览器内上传队列跨刷新保留，重新联网后重试。清除浏览器数据会丢失尚未上传的内容及上传凭证；已上传的对局保留在服务端。服务器和浏览器都离线时不能保证最后一步已上传，因此以“已公开回放”提示为准。
- 导入存档视作一场独立记录，不继承别人或旧分支的上传权限。未完成就弃局的存档保持私有，不会进入公共回放列表。
- 此功能上线前、从未上传且本机也未保留的历史对局无法补回。旧存档在继续游戏时可上传；没有注册系统，不提供跨设备的私人对局找回。
- 当前只是客户端对局的合法记录校验，不是服务器权威联机；不能据此宣称排行榜防作弊。

## 容量与维护

单条请求最多 512 KiB、2000 个行动；每个来源 IP 每分钟最多 120 次写入。默认最多保存 100000 局，可通过 `REPLAY_CAPACITY` 调整。达到容量或存储故障时返回明确错误，前端保留待上传记录。上线后应监测磁盘空间并安排备份；当前不自动删除未完成对局，没有管理后台。更大的并发规模需要迁移数据库、分离校验任务及接入边缘限流。

`REPLAY_RULES` 是规则解释版本。今后修改规则时应保留旧版本的解释能力或做明确迁移；不能只改变引擎行为却沿用相同版本。当前版本同时兼容原固定奖励开局及新的起始位置选择标记。

## API

- `GET /api/health`：服务健康。
- `PUT /api/replays/:uuid`：`Authorization: Bearer <64位十六进制随机凭证>`，JSON 为规则版本、种子、设置与行动。不存在时创建；已存在时要求原凭证，只接受兼容的追加。
- `GET /api/replays?page=1&players=4`：只返回已结束的对局，每页 20 条；人数筛选可省略。
- `GET /api/replays/:uuid`：读取已公开回放，不包含上传凭证。
